# 插件设置页修改中转地址

已注册的电脑可在插件设置页修改服务地址，无需清空本机凭据或编辑配置文件。此功能只修改 DSHM 插件，不修改或构建官方 DSH、SDK、后端或 Android。

维护者：DSHM 插件维护者。核验日期：2026-10-10。任务：[KKC-29](https://linear.app/kkcodes/issue/KKC-29/支持在插件设置页修改中转服务地址)。

## 修改行为与取舍

直接覆盖地址可能把旧电脑凭据交给不同服务，也不能替新后端完成注册。因此分为两个明确入口，成本是一组选择和确认，换来清楚的身份、设备授权与失败行为。

| 入口 | 后端请求及保存行为 |
| --- | --- |
| 同一后端换地址 | 用户确认可信地址后，匿名检测服务，再用当前电脑凭据读取设备列表。通过后保存新地址，不创建新电脑、不更改设备授权。 |
| 更换后端 | 重新检测注册模式。开放模式不读取或发送密钥；个人模式只用本次输入的新密钥。取得新电脑凭据并验证后保存，不向新服务发送旧电脑凭据或旧环境注册密钥。 |

两种入口均要求编辑时的配置版本，提交按序处理。其他窗口已保存或插件重启时，旧表单不能覆盖新配置。检查使用整体十五秒截止时间；保存成功后才停旧通道，按原 enabled 状态决定是否启动新通道。失败和取消保留原连接。持久化格式保持原样，版本标记只保存在运行实例内。

手机当前保存固定服务地址，不会自动迁移。修改后应使用新配对链接重新连接；同后端的旧授权保留，新后端不继承旧授权。旧后端授权不会自动撤销，需要在切换前由用户主动撤销。注册已成功但后续检查或本机保存失败时，新后端可能留下未使用的电脑登记，插件不会因此替换原连接。

## 验证范围

- 自动回归：43 个测试文件、252 项通过，其中管理入口 39 项；覆盖地址校验、确认、现有凭据验证、注册模式、不同后端凭据隔离、失败保持、持久化失败、旧表单、并发提交、启停状态和插件重启。
- 实际入口：在未修改的官方 alpha.2 Web 中，用官方 CLI 安装真实插件归档，独立 DSH_HOME、生产网关与本地 PGlite 数据库验证。同一数据库的两个监听地址验证身份与管理授权保持；另一独立数据库的个人模式服务验证注册失败保持、注册成功的新身份与空设备列表、旧授权不自动撤销、关闭状态保留。375 × 667 下表单、保存与取消可操作，无横向溢出。
- 最终归档：alpha.2 安装后的 63 个文件与归档目录逐项相同，实际验证错误提示、失败后重新编辑、保存及关闭状态、多窗口旧表单拒绝、开放模式更换后端。alpha.1 包已通过官方插件命令安装到现有 `16955` 环境，正常 `pnpm dsh web` 重启；真实插件页编辑和取消通过，原服务地址、电脑身份、启停状态及凭据文件字节保持。该环境没有实际更换用户服务，完整修改流程的实际验证来自独立 alpha.2 环境。
- 最终配置观察：安装与编辑/取消的保持检查通过后，现有 alpha.1 环境又出现了新的中转地址、电脑身份和设备，显示已连接。该变化不属于本次隔离测试，不能再声称收尾时与开工字节完全相同；保留当前新配置，不执行回滚，不将这项观察算作受控公网验收。
- 回归首轮与候选构建并行时，有五项原提供方测试触发默认五秒超时；保留失败记录，未改测试超时。停止并行构建后，串行完整重跑全部通过。
