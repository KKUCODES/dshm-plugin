## 兼容策略

运行时使用 `>=0.2.0-rc.2 <0.3.0-0`，预发布版本按 semver 比较，不再逐个枚举发布号。npm peer 同时声明0.2.0和0.2.1预发布版本线；范围内仍要核验原服务、模块图、bootstrap与remotes入口。范围是尝试兼容的边界，不代表未来每个版本、插件和功能已经测试。

必要服务缺失时在协商阶段返回 `unsupported_dsh_capabilities`，手机还会检查协议通道和加载器接口。定时目录只在官方 Typert 实际注册 `schedule/list` 时宣告，执行时重新检查；不会因为版本在范围内就开放任意接口。固定 SDK 构建矩阵、历史独立alpha.1载荷与范围判定分开。

rc.2 的共享 Fetch 和五参数事件流需要显式 Peer。所有自有 Fetch 调用统一使用原 `browserPeer`，旧版使用原 `operator`；不生成 owner 身份，不接收手机指定身份。配对、设备权限、管理授权及端点白名单均在转发前保持核验。

## 原包与类型限制

只安装官方已发布 npm 包，不执行 SDK 安装脚本、不编译或改写 DSH。rc.2 npm 包缺少部分已导出的 `types.d.ts`，直接类型解析会回退旧环境，不能作为 rc.2 类型通过的证据。自有候选声明沿用 alpha.2 公共类型面，rc.2 运行使用原 rc.2 SDK并另做真实入口验证；旧两版声明构建保留。这个限制没有通过补写官方 SDK 声明来掩盖。

GitHub预编译产物仍由一份自有源码生成。新增 rc.2 SDK配置、CI构建矩阵与本地可重复产物检查；未触发远端 Actions。版本号与公开Release保持原值，本地候选不是新发布包。

协议声明只从当前源码对应的编译项进入安装包，排除切换分支后dist遗留的旧文件；本次排除了原插件适配分支的残留声明，不携带其功能。

## 验证

使用同一份 GitHub 安装载荷，经官方 `dsh plugin --profile web add` 安装到独立 home；生产中转实现使用独立 PGlite 数据库和私有注册配置，不接触用户服务或模型凭据。真实 Android 验证包含配对、批准、工作区读取、聊天输入区、重载重连、原生通知订阅与测试设备撤销。

单元测试覆盖新旧身份参数、缺能力、坏模块图、版本范围、端点权限、文件字节契约和包完整性。具体矩阵与本机报告见下方验证记录。

本次未做真实模型推理、完整Electron/真机/公网验收或每一种插件/Office/审批组合。不把原CLI的Office可选依赖告警描述为Office通过。中转生产协议和服务不需要修改；不混入 `feature/plugin-adaptation`。

### 2026-10-23 实测记录

同一GitHub载荷在原官方CLI `0.2.0-rc.2`、`0.2.1-alpha.2`、`0.2.1-rc.2` 上分别安装；rc.2 SDK手机在三版Host通过上述核心入口和撤销。保留的alpha.2 SDK诊断构建也能进入三版核心聊天，但rc.2 Host上4个界面插件激活失败；正式App因此改用rc.2 SDK，清单无failed项。没有将“能进入聊天”误报为旧SDK的完整兼容。本机报告位于手机仓库忽略目录 `artifacts/rc21/android-<版本>-<测试UID后缀>.json`。插件261项Vitest通过，包/端点Node回归通过，`npm run build:github -- --check` 可重复产物验证通过。

rc.2声明没有完整独立类型通过结论；沿用alpha.2声明面与实际rc.2运行验证的边界保持。新增的旧SDK开发依赖用于恢复现有全套测试，不进入公开运行依赖。
